## 1. 設計支柱、目標玩家、時長

### 1.1 設計支柱（可用來否決提案）

| # | 支柱 | 檢查方式 |
|---|------|----------|
| P1 | **兩種視角缺一不可**：每個謎題都必須同時用到 3D 與 2D 能力，只用一種視角必定解不開 | 每個謎題至少一條「只用單一模式」的反例測試 |
| P2 | **一章一個頓悟**：每章的核心 aha 推翻或延伸前一章建立的直覺（不是換座標） | 第 5 節表格「本章 aha」欄不得重複 |
| P3 | **安靜的推理而非手速**：無計時、無敵人、無精準跳躍要求；失敗成本只有走回去 | 不出現計時器；跳躍高度餘裕 ≥ 0.15（D10）|
| P4 | **物件會說話**：可互動 / 只在某視角存在 / 可蓋印 等狀態一律有形狀符號，不只靠顏色 | 第 7 節無障礙檢查表 |
| P5 | **宅邸就是一張圖**：機制都以「製圖」語彙命名（筆尖、定稿、剖面、落款），劇情與機制同源 | 新機制命名須通過此檢查 |

### 1.2 目標玩家
- 喜歡 Monument Valley、Gris、Portal 一類「短而有頓悟」作品的玩家；不要求平台跳躍技術。
- 會讀短句旁白、願意停下來觀察的玩家；鍵盤操作（WASD / Space / F·Q / E / T / R，見 `puzzle.html`）。

### 1.3 時長估計〔推論〕
| 項目 | 估計 |
|------|------|
| 主線總時長 | 約 4～5.5 小時（50 個主線謎題，各章題均 3.5～8 分；計算見 5.2） |
| 每關 | 8～20 分鐘（Boss 18～22 分為唯一例外） |
| 每章 | 30～65 分鐘，約等於一場實體密室逃脫的長度（實體密室常見 60 分鐘，但本文未找到可信來源佐證「每題幾分鐘」的業界數據 → 推論） |
| 隱藏房 | 3 間各 1 題，每間 10～15 分鐘（另計） |

## 2. 現況機制清單（依程式碼，2026-11-02，commit `1e26b34`）

| # | 機制 | 規則（現況） | 出處 |
|---|------|-------------|------|
| C1 | 兩種視角 | 3D：透視鏡頭斜後上方跟隨；2D：正交鏡頭從 +z 側視，z 被壓平 | `render/cameras.ts` |
| C2 | 壓平碰撞 | 2D 碰撞只看 x、y，忽略 z（任何深度的物體都在同一平面）；2D 只能左右移動（`mz=0`） | `logic/geometry.ts` `overlaps` / `sweepAxis`；`logic/step.ts` |
| C3 | 可見模式 | 物件 `visible: both｜2d｜3d` 同時決定可見、碰撞、互動；`interactIn` 可另限互動模式（如筆尖只能在 2D 拾取） | `logic/types.ts`；`geometry.ts` `solidsFor`；`interact.ts` `canUse` |
| C4 | 跳躍高度差 | 3D 跳高約 1.25（`JUMP_V_3D=8.66`）；2D 約 1.6（`JUMP_V_2D=9.8`）；重力 30、速度 3.2 | `logic/constants.ts` |
| C5 | 推木箱 | 只在 3D、走進去即推、沿單軸；被擋 / 出界 / 中心點失去支撐就停（不能推下地板或推入缺口）；不能連推另一個箱子；木箱沒有重力、不能疊箱 | `logic/push.ts`；`step.ts` `moveAxis` |
| C6 | 圖紙壓板 | `visible:'2d'`；僅在圖紙模式更新；木箱中心 x 落在板的 x 範圍且同高（**任何 z 都算**）即壓下並**永久鎖定**、開啟 `opens` 指定的閘門；玩家太輕壓不動（提示一次） | `logic/mechanisms.ts` `updatePlates` |
| C7 | 閘門 | `type:'gate'`；`used=true` 後不再是實體、不可互動；關閉時互動顯示提示 | `geometry.ts` `isOpenGate`；`interact.ts` |
| C8 | 鑰匙鏈 | 筆尖（`interactIn:'2d'`）→ `hasKey`；墨水閥（2D）需 hasKey → `sealed=false`；出口門需未封印 → `cleared`。**全域單一旗標，寫死在 `interact()` 的 switch** | `interact.ts`；`world.ts` |
| C9 | 互動條件 | 範圍 1.5（2D 忽略 z）；**雙腳站穩才能互動**；看得見卻搆不到時提示「換個角度試試」 | `interact.ts` `findTarget` |
| C10 | 3D→2D 切換 | 在 x-y 平面找最近空位（半徑 3、步長 0.05，向下最多 0.5）；找不到則拒絕「這裡塞不下」；記下 `z3d` | `logic/switchMode.ts`；`logic/place.ts` |
| C11 | 2D→3D 切換 | 還原 `z3d`；若 2D 腳下有支撐物且該物 3D 存在，z 夾到支撐物範圍內；`noLand3d` 區域不可落；優先找「踩得到東西」的落點；找不到則拒絕 | `switchMode.ts` |
| C12 | 木箱歸位 | T：全部木箱回初始位置，壓到玩家則挪到最近空位（通關後無效） | `mechanisms.ts` `resetCrates` |
| C13 | 掉落與檢查點 | y < `voidY` 回重生點（保留目前模式，**木箱不歸位**）；站在地上越過 `checkpoint.minX` 即推進（只會往前） | `world.ts` `respawn` / `updateCheckpoint`；`step.ts` |

| C17 | 測試慣例 | 邏輯層純函式，`tests/puzzle/helpers.ts` 提供 `run / place / walkTo / hopUntil`；`foyerSolution.test.ts` 一條完整通關 + 每謎題反例；`puzzleLogic.test.ts` 機制單元測試 | `tests/puzzle/` |

**現況的隱含規則（設計時要當成「物理定律」）**
- R1：**機關只在它存在的視角更新**（`updatePlates` 跳過非目前模式的壓板）。目前因壓板會鎖定而無感，若加入「非鎖定壓板」就會成為可利用的規則（見 N4）。
- R2：2D 的「位置」只有 x；z 只決定 3D 裡誰擋誰（C2、C6）。玄關與書房都建立在這條直覺上，溫室會刻意推翻它（N6）。
- R3：玩家在 2D 推不動任何東西；能改變世界配置的只有 3D 推箱與互動（C5）。
- R4：可見模式是物件的固定屬性；目前沒有任何方式改變（定稿印 N5 會打破）。

**玄關謎題鏈（現況）**：① 書架過缺口（2D 壓平踩書架）→ ② 推箱到高台旁、2D 踩箱跳上高台取筆尖 → ③ 繞後方窄道把箱推到長桌下的圖紙壓板 x、切 2D 壓下、3D 過閘門 → 2D 墨水閥解封 → 出口門。（`levels/foyer.ts` 註解；`foyerSolution.test.ts`）

**工程限制（擴充前必處理）**：C8 單一旗標寫死、C16 單關寫死、`ObjType` 封閉聯集、壓板只認 `pushable`。見第 10 節 M0。

## 3. 謎題設計原則（可檢查的規則）

| # | 規則 | 依據 | 怎麼檢查 |
|---|------|------|----------|
| D1 | **每個謎題最多一個新概念**；新概念先在「無失敗風險」的小場景出現一次（教），下一題要求主動使用（測），再下一題換條件（變） | 〔來源〕Portal 開發者評論：每個概念都刻意介紹與訓練；任天堂四段式（導入→發展→轉折→收束）〔來源，二手分析〕 | 第 6 節每題新概念 ≤ 1（同一關可依序教多個，如 1-1） |
| D2 | **每個謎題必須同時用到 2D 與 3D**（支柱 P1） | 本作核心 | 每題至少兩條反例測試：只用 3D、只用 2D |
| D3 | **頓悟必須推翻一個合理的錯誤假設**；在謎題說明中寫出「玩家最可能的錯誤嘗試」 | 〔來源〕Blow：刪掉沒有驚喜或彼此重疊的謎題；〔推論〕把錯誤嘗試寫進規格才能確認驚喜存在 | 第 6 節每題有「錯誤嘗試」欄 |
| D4 | **不得有跳過關鍵步驟的捷徑**，以邏輯層測試證明（取樣木箱位置 × 切換點的反例迴圈，比照玄關 `for z of [...]` 寫法） | 現有測試慣例 C17 | 每關反例測試至少覆蓋「關鍵物件在別處」的取樣 |
| D5 | **不放純粹的紅鯡魚**；允許「誘導性錯誤」——看起來可行、試了會學到東西（如玩家站壓板「太輕」） | 〔查不到〕密室社群對紅鯡魚的系統性論述未找到可信來源；〔推論〕安靜詩意基調下，浪費時間的假線索破壞信任 | 每個非必要物件需寫出它教了什麼或屬於哪個隱藏要素 |
| D6 | **規則一致、不臨時例外**：同外觀 = 同規則（Blow 讓所有不受倒帶影響的物件都發綠光）；新規則用新外觀 | 〔來源〕Blow IndieCade 報導 | 機制庫每項都有專屬外觀符號 |
| D7 | **提示分三級**（方向→焦點→步驟），提示把玩家推回邏輯路徑、不直接給答案；同一級提示被超過 50% 玩家使用 → 謎題要重做 | 〔來源〕Room Escape Artist 的提示文章 | 本機統計（第 8 節 `puzzle:stats`）|
| D8 | **錯誤可逆**：任何狀態都能以 T（木箱歸位）、R（重來）或回檢查點復原；不可能進入無解狀態而不自知 | 現有 C12、C13 | 每個新機制需寫「死局如何復原」 |
| D9 | **整合章只允許用已教過的機制**；筆桿機制（第四次升級）在地下室末段 4-3 教、閣樓首關 5-1 測試 / 變奏，之後 Boss 與終章才整合使用 | 〔來源〕Braid / The Witness 先把元素教完，之後難題只在探索已知機制的後果（Blow 相關報導） | 第 5 節第五章「新概念」欄為「—」；6.9 教學順序自檢 |
| D10 | **不靠精準操作**：所有跳躍至少留 0.15 高度餘裕、0.3 水平餘裕；互動一律站穩 | 支柱 P3、現有 C9 | 數值寫進關卡註解並有測試 |

## 7. 提示系統與無障礙

### 7.1 三級提示〔來源：Room Escape Artist——提示是把玩家推回邏輯路徑，不是給答案；同一提示被 ≥50% 隊伍需要即該修謎題〕

| 級 | 內容 | 解鎖（已確認：計時解鎖，設定可改「隨時 / 關閉」） | 呈現 |
|----|------|-------------------------|------|
| 1 方向 | 一句詩意的方向（現有紙條即此級，如「有些重量，只在紙上才算數。」） | 進入謎題 3 分鐘 | 紙條 / 旁白 |
| 2 焦點 | 標出本題相關物件（描邊 + 符號），並說明哪個視角 | 再 3 分鐘，或主動按 H | 物件閃現描邊 |
| 3 步驟 | 下一步具體動作（「把書車推到迴廊左緣旁」） | 再 4 分鐘，且需按 H 兩次確認 | HUD 文字 |

- **卡關偵測**〔推論〕：以謎題進度旗標為單位；同一謎題內 T 歸位 ≥ 3 次、或切換 ≥ 12 次無新旗標、或掉落 ≥ 3 次 → 提前解鎖下一級（只亮提示圖示，不自動顯示）。
- 每題在關卡資料定義 `hints: [string, objIds[], string]` 與進度旗標；測試檢查 50 題（+ 隱藏 3）三級齊全。
- 現有「看得見，卻碰不到。換個角度試試。」（C9）保留為 0 級即時回饋。

### 7.2 無障礙
| 項目 | 規格 | 依據 |
|------|------|------|
| 不只靠顏色 | 只在 2D 存在的物件加「墨點」符號；只在 3D 存在的加「實線框」；可蓋印物有方形印框；剖面中的物件有斜線填紋；墨記在 3D 顯示為橫跨所有深度的墨線、在 2D 為一個墨點（形狀區分）；壓板顯示需要的重量（點數）；影子以網點紋區分實體影子與裝飾陰影 | 〔來源〕Xbox 無障礙準則 103：不要讓任何提示只靠顏色；可讓玩家自選顏色 |
| 色盲模式 | 2D 墨水色可切換三組（預設 / 藍橙 / 高對比黑白紋理） | 同上 |
| 視角提示 | HUD 現有「現實 / 圖紙」文字（`hud.ts` `setMode`）保留；剖面開啟時加「剖面」字樣 | 現況 |
| 減少動態 | 切換過場（`game.ts` 墨水暈開）可改為淡入淡出；不做 Fez 式強制旋轉 | 〔來源〕Fez 旋轉致暈的批評 |
| 回溯 | T 木箱歸位、R 重來、檢查點（現有）；新增「回到本謎題開始」 | D8 |
| 操作 | 全按鍵可重綁；不需同時按兩鍵；無計時 | P3 |

## 8. 進度與存檔（localStorage，前綴 `puzzle:`）

| Key | 內容（JSON） | 寫入時機 |
|-----|-------------|----------|
| `puzzle:save` | `{ v:2, cleared:string[] /* '1-1'…'6-1','H1'…'H3' */, current:string, abilities:('nib'｜'pin'｜'section'｜'mark')[], diary:number[] /* 1..5 */, scraps:number[] /* 1..6 */, endings:{A:boolean,B:boolean} }` | 每關通關、取得能力 / 碎片時 |
| `puzzle:settings` | `{ hints:'timed'｜'always'｜'off', inkPalette:'default'｜'blueOrange'｜'mono', reduceMotion:boolean, keys:{...} }` | 設定變更 |
| `puzzle:stats` | `{ [puzzleId]: { time:number, hints:[n1,n2,n3], resets:number } }`（只存本機，供試玩調整 D7） | 謎題完成 |

- **遷移**：讀到舊 `puzzle:foyer:cleared='1'` → 寫入 `cleared:['1-1','1-2']`、`abilities:['nib']`（舊玄關即新 1-2；1-1 門廊視為已通過以免老玩家重教），刪除舊 key。
- **關內不存檔**（已確認）；Boss 5-5 三階段之間有關內檢查點（不寫入存檔）。墨記不跨關保留。
- **章節解鎖**：線性解鎖；5-2、5-3、5-4 在 5-1 通關後同時開放；5-5 需三翼皆完成；6-1 需 5-5；隱藏房在取得所需能力後於章節選單顯示入口。
- **重玩規則**：`LevelDef.abilities` 決定該關可用能力（防新能力破解舊關）；隱藏房入口例外。
- **結局旗標**：`endings.A` 於結局 A 寫入；`endings.B` 於結局 B 寫入（需 `scraps` 1～6 齊全）。

| 里程碑 | 內容 | 新增邏輯 | 量 | 測試策略 | 風險 / 取捨 |

| **M1 垂直切片：玄關章 + 書房章** | 8 關 22 題（核心 17 / 擴充 5）：1-1～1-3、2-1～2-5；N1、N2、N4、N5、N13、N14、`heavy`、N10；三級提示 + 卡關偵測 + `puzzle:stats` | `updatePlates` 計數 / 非鎖定 / 反向 / 只算當前視角存在的箱；`ObjState.pinned` 與有效可見性；移印承載檢查 | **L** | 每關一條完整通關路徑 + 每題反例（只用 3D、只用 2D、關鍵物件在別處）；**捷徑掃描**：每個可推物網格取樣 × 兩模式，斷言關鍵旗標不成立（比照玄關 `for z of [...]`） | 最重的一段；N5 最易多解 → `pinnable` 白名單 |
