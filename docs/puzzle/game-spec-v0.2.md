## 1. 設計支柱、目標玩家、時長

### 1.1 設計支柱（可用來否決提案）

| # | 支柱 | 檢查方式 |
|---|------|----------|
| P1 | **兩種視角缺一不可**：每個謎題都必須同時用到 3D 與 2D 能力，只用一種視角必定解不開 | 每個謎題至少一條「只用單一模式」的反例測試 |
| P2 | **一章一個頓悟**：每章的核心 aha 推翻或延伸前一章建立的直覺（不是換座標） | 第 5 節表格「本章 aha」欄不得重複 |
| P3 | **輕鬆的推理而非手速**：無計時、無敵人、無精準跳躍要求；失敗成本只有走回去；章末考 / Boss / 終章的緊張效果只屬呈現層、**不構成威脅、不會導致失敗**（9.1） | 不出現計時器；跳躍高度餘裕 ≥ 0.15（D10）|
| P4 | **物件會說話**：可互動 / 只在某視角存在 / 可蓋印 等狀態一律有形狀符號，不只靠顏色 | 第 7 節無障礙檢查表 |
| P5 | **在遊戲裡修遊戲**：機制都以遊戲開發語彙命名（畫筆工具、提交、剖面檢視、標記點；顯示名見 story-bible 對照表），劇情與機制同源 | 新機制命名須通過此檢查 |

### 1.2 目標玩家
- **國中到高中的青少年**；喜歡 Monument Valley、Portal 一類「短而有頓悟」作品，不要求平台跳躍技術。
- 文案短、直白、有一點幽默（劇情：遊戲社的你被吸進社團做到一半的遊戲，見 `story-bible-v0.1.md`）；鍵盤操作（WASD / Space / F·Q / E / T / R，見 `puzzle.html`）。

### 1.3 時長估計〔推論〕
| 項目 | 估計 |
|------|------|
| 主線總時長 | 約 4～5.5 小時（50 個主線謎題，各章題均 3.5～8 分；計算見 5.2） |
| 每關 | 8～20 分鐘（Boss 18～22 分為唯一例外） |
| 每章 | 30～65 分鐘，約等於一場實體密室逃脫的長度（實體密室常見 60 分鐘，但本文未找到可信來源佐證「每題幾分鐘」的業界數據 → 推論） |
| 隱藏房 | 3 間各 1 題，每間 10～15 分鐘（另計） |

## 2. 現況機制清單（依程式碼，2026-11-02，commit `1e26b34`）

| # | 機制 | 規則（現況） | 出處 |
|---|------|-------------|------|
| C1 | 兩種視角 | 3D：透視鏡頭斜後上方跟隨；2D：正交鏡頭從 +z 側視，z 被壓平 | `render/cameras.ts` |
| C2 | 壓平碰撞 | 2D 碰撞只看 x、y，忽略 z（任何深度的物體都在同一平面）；2D 只能左右移動（`mz=0`） | `logic/geometry.ts` `overlaps` / `sweepAxis`；`logic/step.ts` |
| C3 | 可見模式 | 物件 `visible: both｜2d｜3d` 同時決定可見、碰撞、互動；`interactIn` 可另限互動模式（如筆尖只能在 2D 拾取） | `logic/types.ts`；`geometry.ts` `solidsFor`；`interact.ts` `canUse` |
| C4 | 跳躍高度差 | 3D 跳高約 1.25（`JUMP_V_3D=8.66`）；2D 約 1.6（`JUMP_V_2D=9.8`）；重力 30、速度 3.2 | `logic/constants.ts` |
| C5 | 推木箱 | 只在 3D、走進去即推、沿單軸；被擋 / 出界 / 中心點失去支撐就停（不能推下地板或推入缺口）；不能連推另一個箱子；木箱沒有重力、不能疊箱 | `logic/push.ts`；`step.ts` `moveAxis` |
| C6 | 圖紙壓板 | `visible:'2d'`；僅在圖紙模式更新；木箱中心 x 落在板的 x 範圍且同高（**任何 z 都算**）即壓下並**永久鎖定**、開啟 `opens` 指定的閘門；玩家太輕壓不動（提示一次） | `logic/mechanisms.ts` `updatePlates` |
| C7 | 閘門 | `type:'gate'`；`used=true` 後不再是實體、不可互動；關閉時互動顯示提示 | `geometry.ts` `isOpenGate`；`interact.ts` |

| C9 | 互動條件 | 範圍 1.5（2D 忽略 z）；**雙腳站穩才能互動**；看得見卻搆不到時提示「換個角度試試」 | `interact.ts` `findTarget` |
| C10 | 3D→2D 切換 | 在 x-y 平面找最近空位（半徑 3、步長 0.05，向下最多 0.5）；找不到則拒絕「這裡塞不下」；記下 `z3d` | `logic/switchMode.ts`；`logic/place.ts` |
| C11 | 2D→3D 切換 | 還原 `z3d`；若 2D 腳下有支撐物且該物 3D 存在，z 夾到支撐物範圍內；`noLand3d` 區域不可落；優先找「踩得到東西」的落點；找不到則拒絕 | `switchMode.ts` |
| C12 | 木箱歸位 | T：全部木箱回初始位置，壓到玩家則挪到最近空位（通關後無效） | `mechanisms.ts` `resetCrates` |
| C13 | 掉落與檢查點 | y < `voidY` 回重生點（保留目前模式，**木箱不歸位**）；站在地上越過 `checkpoint.minX` 即推進（只會往前） | `world.ts` `respawn` / `updateCheckpoint`；`step.ts` |

**現況的隱含規則（設計時要當成「物理定律」）**
- R1：**機關只在它存在的視角更新**（`updatePlates` 跳過非目前模式的壓板）。目前因壓板會鎖定而無感，若加入「非鎖定壓板」就會成為可利用的規則（見 N4）。
- R2：2D 的「位置」只有 x；z 只決定 3D 裡誰擋誰（C2、C6）。玄關與書房都建立在這條直覺上，溫室會刻意推翻它（N6）。
- R3：玩家在 2D 推不動任何東西；能改變世界配置的只有 3D 推箱與互動（C5）。
- R4：可見模式是物件的固定屬性；目前沒有任何方式改變（定稿印 N5 會打破）。

**玄關謎題鏈（現況）**：1-2a 書架過缺口（2D 壓平踩書架）→ 1-2b 推箱到高台旁、2D 踩箱跳上高台取筆尖 → 1-2c 繞後方窄道把箱推到長桌下的圖紙壓板 x、切 2D 壓下、3D 過閘門 → 2D 墨水閥解封 → 出口門。（`levels/foyer.ts` 註解；`foyerSolution.test.ts`）

**工程限制（擴充前必處理）**：C8 單一旗標寫死、C16 單關寫死、`ObjType` 封閉聯集、壓板只認 `pushable`。見第 10 節 M0。

## 3. 謎題設計原則（可檢查的規則）

| # | 規則 | 依據 | 怎麼檢查 |
|---|------|------|----------|
| D1 | **每個謎題最多一個新概念**；新概念先在「無失敗風險」的小場景出現一次（教），下一題要求主動使用（測），再下一題換條件（變） | 〔來源〕Portal 開發者評論：每個概念都刻意介紹與訓練；任天堂四段式（導入→發展→轉折→收束）〔來源，二手分析〕 | 第 6 節每題新概念 ≤ 1（同一關可依序教多個，如 1-1） |
| D2 | **每個謎題必須同時用到 2D 與 3D**（支柱 P1） | 本作核心 | 每題至少兩條反例測試：只用 3D、只用 2D |
| D3 | **頓悟必須推翻一個合理的錯誤假設**；在謎題說明中寫出「玩家最可能的錯誤嘗試」 | 〔來源〕Blow：刪掉沒有驚喜或彼此重疊的謎題；〔推論〕把錯誤嘗試寫進規格才能確認驚喜存在 | 第 6 節每題有「錯誤嘗試」欄 |
| D4 | **不得有跳過關鍵步驟的捷徑**，以邏輯層測試證明（取樣木箱位置 × 切換點的反例迴圈，比照玄關 `for z of [...]` 寫法） | 現有測試慣例 C17 | 每關反例測試至少覆蓋「關鍵物件在別處」的取樣 |
| D5 | **不放純粹的紅鯡魚**；允許「誘導性錯誤」——看起來可行、試了會學到東西（如玩家站壓板「太輕」） | 〔查不到〕密室社群對紅鯡魚的系統性論述未找到可信來源；〔推論〕浪費時間的假線索會破壞玩家對謎題的信任，對青少年玩家尤其容易直接放棄 | 每個非必要物件需寫出它教了什麼或屬於哪個隱藏要素 |
| D6 | **規則一致、不臨時例外**：同外觀 = 同規則（Blow 讓所有不受倒帶影響的物件都發綠光）；新規則用新外觀 | 〔來源〕Blow IndieCade 報導 | 機制庫每項都有專屬外觀符號 |
| D7 | **提示只用場景便利貼，適量、抽象、不破題**（意象 → 觀察問題 → 缺口的形狀；每題 0～3 張依預算，7.1.3），不給動作、不點名物件、不給數字、不點出 aha 依賴的性質（量表 7.1.1，H10）；同一級便利貼被超過 50% 玩家需要 → 謎題要重做；攻略筆記被 ≥ 20% 打開 → 重做 | 〔來源〕Room Escape Artist 的提示文章 | 本機統計（第 8 節 `puzzle:stats`）＋ 驗證器（7.1.1）|

## 4. 機制擴充庫

| ID | 機制 | 規則（一句話） | 與 2D/3D 的關係 | 成本 | 謎題範式 | 風險 / 衝突處理 | 排入 |

| N1 | 投影疊合 | 不同深度的物體在 2D 裡只按 x 排列：箱子能在紙上「疊在同一格」、能接成階梯 | 純粹是 C2 的推論 | **〔現有〕** 0 | 3D 推箱排出 2D 階梯；3D 擠不下的兩個箱子在紙上重疊 | 意外捷徑多 → 反例測試取樣 | 書房 |

## 7. 提示系統與無障礙

### 7.1 提示：場景裡的便利貼（適量、抽象、不破題）〔來源：Room Escape Artist——提示是把玩家推回邏輯路徑，不是給答案；同一提示被 ≥50% 隊伍需要即該修謎題〕

使用者決定：**不設會跟玩家說話的提示角色**（原 AI 小助手「小格」整個移除），提示只用場景裡的便利貼——延續現有 `note` 物件（靠近、站穩、按 E 閱讀，C9、C14）。便利貼是社長開發時貼在各處的備忘。提示要**適量、抽象、不破題**，動作永遠由玩家自己組出來。

| 級 | 形式 | 給什麼 | 字數上限（署名不計） | 出現方式 |
|----|------|--------|---------------------|---------|
| L1 意象 | 一開始就貼在謎題附近的便利貼 | 方向感、情緒或意象；不碰機制 | 24 字 | 進入關卡即可讀 |
| L2 觀察問題 | 原本**空白**的便利貼，時間到才浮現字跡 | 一個觀察問題 | 30 字 | 進入謎題 4 分鐘，或卡關偵測提前；浮現時便利貼**邊角微微發亮**，不彈窗、不對話、不打斷 |
| L3 缺口的形狀 | 同上 | 只指出「還缺什麼樣的東西」，不指出怎麼補 | 36 字 | 進入謎題 8 分鐘，或卡關偵測提前 |
| L4 攻略筆記（安全閥，暫定，待確認 Q-D） | **不在場景裡**：暫停選單「社長的攻略筆記」頁 | 逐步解法 | 不限 | 見 7.1.2；預設關閉，需主動開啟並確認警語 |

- **節奏**（沿用 Q3「計時解鎖」，改在場景內呈現）：L1 不計時；L2、L3 的空白便利貼一開始就貼好，時間到才浮現字跡。設定「提示：計時 / 隨時 / 關閉」照舊——「隨時」= 空白便利貼一開始就有字；「關閉」= L2、L3 便利貼不放（L1 仍在，因為它是場景的一部分）。
- **敘事**：社長在設計這個密室遊戲時，做了一種「延遲顯色便利貼」當作遊戲的提示系統；被吸進來後她自己也忘了寫過什麼（「我有寫這張？」）。卡關偵測 = 遊戲偵測到你一直重置、一直切換，讓字早一點顯出來。
- **卡關偵測**〔推論〕：以謎題進度旗標為單位；同一謎題內 T 歸位 ≥ 3 次、或切換 ≥ 12 次無新旗標、或掉落 ≥ 3 次 → 下一張空白便利貼提前顯字。只作用於 L2、L3，不會打開 L4。
- **H 鍵**：只用來**重看本關已出現過的便利貼**（唯讀清單，不會叫出新提示）。
- **資料格式**：每題 0～3 張提示便利貼，依 7.1.3 預算；每張是關卡裡的 `note` 物件，帶 `hint: { puzzle, level, truthRef }`；每題另有 `keyObjects`（H4 檢查用）、`solutionKey`（L4）。詳見 `architecture-v0.2.md` 4.10。
- C9「看得見，卻碰不到。換個角度試試。」保留為即時規則回饋（系統訊息，無說話者），不算提示、不受量表限制。
- 範例（1-1～1-3、2-1 全部謎題）與破題檢查見 story-bible 7.3。

#### 7.1.2 安全閥評估（暫定，待確認 Q-D）

| 方案 | 優點 | 缺點 | 評估 |
|------|------|------|------|
| (a) 只有便利貼（適量、抽象） | 最好玩、最安靜、最一致 | 便利貼變少又更抽象，青少年卡太久容易直接放棄；一題卡死 = 整章卡死（線性） | 單獨不夠 |
| (b) 暫停選單「社長的攻略筆記」頁 + 擴充題可「跳過此題」 | 保證不會永久卡關；不在場景裡、沒有角色口吻，不破壞氣氛 | 太容易打開就會被濫用 | **採用**，預設關、要主動開、要等、要確認 |
| (c) 卡關偵測讓空白便利貼提前顯字（沿用） | 卡住的人更快拿到抽象便利貼 | 只加速 L2、L3 | **採用**，不得打開 L4 |

**建議（暫定值）**：(a)+(b)+(c)。因為便利貼變少、更抽象，**L4 的重要性上升**，但仍維持預設關閉、需主動開啟：
- 攻略筆記頁在暫停選單，按謎題列出；某題要在**進入謎題 10 分鐘後**才可打開（卡關偵測可縮到 6 分鐘，因為很多題沒有 L2 / L3，不能用「L3 出現後」當條件）；打開前顯示警語「看了就沒有『想通』的那一刻囉。」並需再按一次確認。
- 設定「攻略模式」（預設關，開啟時同樣顯示警語）：開啟後攻略筆記頁不必等待。
- 「跳過此題」只在攻略筆記頁裡、只限擴充題（核心題會斷教學鏈）。
- 統計：某題 ≥ 20% 試玩者打開攻略筆記 → 該題或其便利貼要重做（比 D7 的 50% 更嚴，因為等同看答案）。

| 3～4.5 | 1 | 0（標「易卡關」才放） | 0 |

## 9. 劇情與文案骨架（摘要；完整內容見 `story-bible-v0.1.md`）

### 9.1 緊張感設計（只用於章末考、Boss 與終章）

**已確認（方向）**：採「環境壓力」「音樂與聲音」「視覺與鏡頭」三類手法；不新增機制風險，不改結構節奏（章首喘息、Boss 三階段與檢查點維持不動）。**暫定，待確認**：適用範圍、強度與參數（Q-F、Q-G）。原「局部詭異」已取消（與輕鬆調性不協調）。敘事文案（字條、台詞）**待新劇情定稿後補**，本節只定義呈現規則；程式落點見 architecture 4.13。

**護欄（全部必須遵守）**
- P3 仍成立：無敵人、**無真實計時**、不會因為慢或錯而失敗；緊張效果不碰玩家、不擋路、不推物件、不改任何旗標。

- 可讀性底線：謎題物件、P4 形狀符號、便利貼、互動提示在暈影與色溫下仍清楚（參數見下）。
