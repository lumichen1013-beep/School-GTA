## 1. 演出目標與原則

| # | 原則 | 理由 |
|---|------|------|
| 1 | **只在「玩家需要知道新東西」時演**：前提（序章）、每章揭露一件關於爸爸或試煉的事、真相（撕圖那晚）、目標（三扇天窗）、結局 | 過場越多越打斷解謎；每場都要回答「此刻玩家需要知道 / 感受到什麼」 |
| 2 | **插在章末，不插在謎題中間** | 章末是自然的休息點；不打斷「想」的節奏（與規格 9.1「驚嚇只在謎題完成後」一致） |
| 3 | **慢**：手動推進為主、每段有最短停留、一次只出一段話 | 使用者要求「訊息呈現要慢」；玩家同時在看畫面（第 2 節） |
| 4 | 安靜帶一點不對勁，但**過場裡不做驚嚇** | 驚嚇已集中在遊戲中（規格 9.1）；過場是理解與情緒的地方 |
| 5 | 每場只有一件事：一頁筆記或手記、一次重組、一個畫面 | 高中玩家讀得懂；避免一次塞太多 |

## 2. 訊息呈現速度規則（可檢查）

### 2.1 依據
| 來源 | 數字 | 狀態 |
|------|------|------|
| Netflix 繁體中文字幕指南 | 閱讀速度上限：成人節目**每秒 9 字**、兒童節目**每秒 7 字**；字級以畫面能容納約 16 字為準 | 〔來源〕搜尋摘要；未逐字核對原文 |
| Netflix 一般規範 | 半形字元與標點計 0.5 字（各語言另有規定者除外） | 〔來源〕 |
| 第三方中文字幕業者 | 每秒 12～15 字 | 〔來源〕但與 Netflix 不一致，不採用 |
| 遊戲無障礙整理 | 過場應可暫停、跳過、重看，並提供完整字幕、可調字級與對比、文字紀錄 | 〔來源〕Game Accessibility Guidelines、遊戲無障礙文章（見參考資料） |
| 閱讀速度研究 | — | 〔查不到〕本次未找到可信的中文遊戲文字閱讀速度研究，不引用數字 |

### 2.2 規則（本作採用，比來源更慢）
- **速度上限：每秒 6 字**（一般）；設定「慢」為每秒 4.5 字。比 Netflix 兒童節目的 7 字還慢，理由：過場時玩家同時要看畫面構圖與動態，且詭異調性需要留白〔推論〕。
- **每段停留時間公式**：`T = max(3.0, 1.5 + n ÷ 6 + 停頓)` 秒
  - `n` = 字數：中文與全形字計 1；半形英數計 0.5；標點不計；`{name}` 在驗證時以上限 12 字計（執行時用實際暱稱）。
  - 停頓：`，、；：` 各 0.2 秒；`。！？` 各 0.4 秒；`……` 0.6 秒。
  - `1.5` 秒 = 開始讀之前的定位時間；`3.0` 秒 = 任何一段的最短停留。
  - 「慢」設定時把 6 換成 4.5。
- **一個畫面最多 2 行、每行 ≤ 16 字**（每段 ≤ 32 字；本文件實際每段 ≤ 24 字）。16 字取自 Netflix 的字級基準，本作把它當作每行上限〔推論〕。
- **一次只顯示一段**；同一鏡有兩段以上時依序出現，上一段淡出後下一段才淡入。
- **鏡頭秒數** = `max(該鏡各段 T 之和, 視覺最短秒) + 轉場秒`；轉場：淡入 / 淡出 1.0、交叉淡化 0.8、墨水暈開 1.0、翻頁 0.8、紙裂 1.2、切 0。

### 2.3 推進方式
| 項目 | 規格 |
|------|------|
| 預設 | **手動推進**：點擊 / 點一下畫面、Enter、空白鍵、E 進下一段 |
| 防誤觸 | 每段文字**完全淡入後再過 1.2 秒**才接受推進（`minDwell`）；在此之前的輸入丟棄 |
| 自動播放（設定 `autoAdvance`，預設關） | 每段停留 `T` 秒後自動進下一段；任何推進輸入可提前 |
| 跳過整段過場 | 長按（1 秒，圓環進度）或畫面角落「跳過」按鈕 → **確認窗**（沿用重新進房確認窗樣式與 300 ms 保護）；設定 `skipConfirm`（預設開） |
| 重看 | 選單「回憶」頁列出已看過的過場，可重看；重看時可直接跳過，不需確認 |
| 文字紀錄 | 暫停 / 回憶頁可看本場已顯示的全部文字（無障礙） |
| 記錄 | 看完或跳過都寫入 `puzzle:save.seenCutscenes`（`puzzle:` 前綴）；跳過的過場在回憶頁標示「未看完」 |
| 暫停 | 失焦、切到背景時暫停時間軸（沿用 `releaseAll` 時機） |

### 2.4 文字動畫與可讀性
- 預設**整段淡入**（0.4 秒）、淡出（0.3 秒）；不使用逐字打字效果。若日後加打字效果，上限每秒 20 字，且仍以整段 `T` 計停留〔推論〕。
- 文字淡入的 0.4 秒內，畫面不得有強動態（運鏡速度在文字出現時減半；不同時做轉場）。
- 「減弱動態」（`reduceMotion`）：運鏡改為靜止或極慢、轉場一律改為 0.6 秒淡入淡出、無視差。
- 字級下限：桌機 22 CSS px、手機 20 CSS px（隨 `noteScale` 放大）；文字與底色對比 ≥ 4.5:1（WCAG 1.4.3 一般文字標準〔來源：WCAG〕）。
- 字幕帶：畫面下方 22% 的奶油紙半透明帶（不透明度 0.85）；**構圖重點一律放在上方 3/4**，字幕不遮住重要畫面；手機直屏時字幕帶加高到 28%。
- 說話者標示：引號內是說話者的話；需要時在前面加名字（例：「爸爸：」）；本版逐字稿以「爸爸說：」寫在句中，不另加標示。

### 2.5 聲音
- 過場總輸出 ≤ -14 dBFS，經規格 9.1 的限幅器；環境音峰值 ≤ -24 dBFS、起音 ≥ 150 ms。
- **過場不放驚嚇音**；撕紙聲是本文件唯一的「明顯」音效（≤ -18 dBFS、起音 ≥ 150 ms，`cs:night` 第 4 鏡）。
- 文字出現時不放新的明顯音效（避免同時搶注意力）。
- 「減弱緊張效果」開啟時，`cs:night` 的低頻長音與撕紙聲降一半音量。

## 5. 美術方向與製作方式

不引入外部圖檔素材，全部用程式繪製；風格與遊戲一致（**森林中的圖書館**：奶油羊皮紙底、深棕描邊、同色系扁平色塊、暖黃燈火、墨水藍與淡青螢光點綴、森林綠透光；色板見 story-bible 8.2，實際值從 `render/themes` 取）。

| 方案 | 做法 | 優點 | 缺點 | 風格一致性 | 工作量 | 手機效能 |
|------|------|------|------|-----------|-------|---------|
| A 向量剪紙分鏡 | 每鏡用 SVG（或 Canvas 2D）畫 2～4 層剪紙圖層，加視差、緩推、淡入淡出 | 與遊戲的藏寶圖視角（2D 剪紙）同一種美術語言；向量在高 DPI 手機清晰；可畫任何場景（山路、回憶、魔方剖面） | 每個畫面都要用程式畫圖形，構圖越多越費工；需要一套剪紙圖形小工具（紙張邊緣、描邊、陰影） | 高 | M～L（約 48 鏡；可共用元件） | 好（DOM / Canvas 2D 很輕） |
| B 沿用 three.js 場景 | 重用現有房間與模型，只做鏡頭路徑與燈光變化 | 和遊戲畫面完全一樣；室內鏡頭幾乎零美術成本 | 戶外、回憶、魔方剖面、特寫都沒有現成模型，要另做 3D 模型；鏡頭運動要小心穿模 | 高（室內）；低（缺模型的場景） | L | 中（同遊戲渲染成本） |
| C 混合（**主推**） | 以 A 為主；**只在場景已存在的鏡頭用 B**（序章第 9 鏡門廊、`cs:ch3` 溫室、`cs:attic` 閣樓、結局的林心草地與牆後的門） | 戶外、回憶、魔方剖面、特寫用剪紙畫得出來；室內鏡頭沿用真實場景，讓玩家認得「就是剛剛那裡」；2D 剪紙與藏寶圖視角互相呼應 | 兩套呈現要接在一起（轉場要統一用墨水暈開 / 淡化）；引擎鏡頭依賴關卡已製作 | 高 | M～L | 好 |

**主推 C 的理由**：本作的 2D 視角本來就是剪紙風，A 讓過場和「藏寶圖」是同一種畫；需要真實空間感的少數鏡頭用 B，成本最低。引擎鏡頭的關卡尚未製作時（例如 5-1、6-1），先用 A 的剪紙版本代替，關卡完成後再換。

**剪紙圖形元件**（A 的共用工具，`render/cutscene/paper.ts`）：紙張不規則邊緣、2px 深棕描邊、3px 偏移陰影、紙張紋理（程式產生）；人物剪影（爸爸、小時候的你、玩家、守衛殘影）；森林圖書館元件（高書架、木梯、迴廊、樹根、藤蔓、苔蘚、半浮的書與羊皮紙、彩繪玻璃、星圖）；試煉元件（魔法陣刻紋與發光、鋼筆與筆身字、「許」字火漆印、魔方剖面方塊與門的接線）；常用物件（筆記本、字條、手記頁、老宅圖殘片、地毯、手機訊號格）。人物一律剪影或背影，不畫臉部細節（呼應「殘影」設定，也降低製作量）。

**舊元件的去留**（M1C 已依舊版序章實作，程式由另案改）：舊版專用元件（見修訂紀錄）不再使用；鋼筆、火漆印、人物剪影、山路與老宅沿用。

## 6. 技術設計

### 6.1 位置與分層
| 檔案 | 層 | 職責 | 可否 Node 測試 |
|------|----|------|--------------|
| `content/cutsceneTypes.ts` | content | 純型別（零依賴），供 ui / render 以 `import type` 使用（比照 `moodTypes.ts`） | — |
| `content/cutscenes/*.ts` | content | 每場一檔：鏡頭、文字 key、轉場、音訊提示 | — |
| `text/readingTime.ts` | text | **閱讀時間公式**（第 2.2 節），純函式 | 是 |
| `app/cutscene.ts` | app | 時間軸狀態機：目前鏡、目前段、淡入 / 停留 / 淡出階段、`minDwell`、自動播放、跳過確認、暫停；不碰 DOM | 是 |
| `ui/cutscene.ts` | ui | 字幕帶、跳過按鈕、長按進度、確認窗；文字由 key 取得 | — |
| `render/cutscene/` | render | 剪紙分鏡（SVG / Canvas）與引擎鏡頭（重用 `PuzzleScene` + 鏡頭路徑） | — |
| `audio/synth.ts` | audio | 依 `audio` 提示播放（規格 9.1 的模組） | — |

**依賴矩陣**：不新增邊。`ui/cutscene.ts`、`render/cutscene/` 對 content 只 `import type` `content/cutsceneTypes.ts`（2.3 加入例外清單）；`app` 負責把資料交給它們；`devtools/validate.ts` 可 import content 與 text（既有權限）。`core/`、`mechanics/` 不知道過場存在。

### 6.2 資料格式
```ts
// content/cutsceneTypes.ts
export type CutsceneId = 'cs:prologue' | 'cs:ch1' | 'cs:ch2' | 'cs:ch3' | 'cs:night' | 'cs:attic' | 'cs:endA' | 'cs:endB';
export interface CutsceneDef {
  id: CutsceneId;
  titleKey: TextKey;                       // 回憶頁顯示
  trigger: { afterClear?: string; beforeFirst?: string; ending?: 'A' | 'B' };
  replayable: true;
  shots: ShotDef[];
}
export interface ShotDef {
  art: { kind: 'paper'; sceneId: string; layers?: Record<string, unknown> }
     | { kind: 'engine'; levelId: string; camera: CameraPath };
  motion?: { push?: number; parallax?: number; panX?: number; durSec?: number };   // 減弱動態時忽略
  transitionIn: 'fade' | 'crossfade' | 'inkBleed' | 'pageTurn' | 'paperTear' | 'cut';
  lines: TextKey[];                        // 每個 key 一段（≤ 2 行 × 16 字）；可含 {name}
  minVisualSec?: number;                   // 視覺最短秒（例：標題卡）
  audio?: Array<{ at: 'start' | 'line' | 'end'; cue: string }>;
}
// text/readingTime.ts
export function readingSeconds(s: string, opt: { cps: number /* 6 或 4.5 */; nameLen?: number }): number;  // = max(3, 1.5 + n/cps + 停頓)
```
- 鏡頭秒數**不寫在資料裡**，一律由 `readingSeconds` 與 `minVisualSec` 算出，避免手寫秒數與文字不一致。
- 文字 key：`cs.<id>.<鏡>.<段>`，例 `cs.prologue.11.3` = 「「我試了一輩子，從沒成功。」」、`cs.endA.9.1` = 「{name}，暑假結束了。」；插值參數 `{ name: save.name }`。
- 畫面狀態機新增 `{ id: 'cutscene'; cutsceneId; next: Screen }`：
  - 暱稱完成 → 若未看過 `cs:prologue` → `cutscene(prologue, next: level 1-1)`。
  - `clear` 畫面「下一關 / 回選單」之前，若該關有 `afterClear` 過場且未看過 → 先進 `cutscene`。
  - 結局：6-1 通關 → `cutscene(endA | endB, next: menu)`。
  - 選單「回憶」→ `cutscene(id, next: menu)`（重看）。
- 輸入：沿用 `InputSource`；推進 = `confirm`、`interact`、`jump` 或點擊 / 觸控點一下；跳過 = 長按或跳過按鈕 → 確認窗（重用 `RestartConfirm` 的 300 ms 保護邏輯，改名或泛化為 `ConfirmGate`）。
- 設定（規格 8）：`autoAdvance`（預設 false）、`textSpeed: 'normal' | 'slow'`（6 / 4.5 字每秒）、`skipConfirm`（預設 true）；沿用 `reduceMotion`、`noteScale`、`calmTension`。
- 存檔（規格 8）：`seenCutscenes: string[]`、`skippedCutscenes: string[]`（回憶頁標示用）。
- 音訊：`audio` 提示交給規格 9.1 的 `PuzzleAudio`；過場總輸出上限 -14 dBFS。

### 6.3 測試策略
| 類型 | 內容 |
|------|------|
| 單元（Node） | `readingSeconds`：純中文、含標點、含半形、含 `{name}`、最短 3 秒、慢速；時間軸狀態機：淡入完成前與 `minDwell` 內的推進被丟棄、之後有效；自動播放依 `T` 前進；跳過需確認（`skipConfirm` 關時直接跳過）；暫停時時間不前進；重看不需確認 |
| 驗證器 | 每段 ≤ 2 行 × 16 字、`{name}` 以 12 字計；每場總長落在目標區間（序章 60～110 秒、結局 60～90 秒、其他 20～45 秒）；每個 `TextKey` 存在；轉場名合法；`engine` 鏡頭的 `levelId` 已登錄（未登錄時必須有 `paper` 替代）；無驚嚇提示（`cs:night` 的撕紙聲除外且符合音量上限） |
| Playwright | 新存檔：暱稱 → 序章 → 1-1；手動推進與防誤觸；長按跳過 → 確認 → 進 1-1，存檔有 `seenCutscenes`；回憶頁重看；手機模擬下字幕帶不遮按鈕、字級 ≥ 20 px |
| 人工 | 可讀性（桌機、手機直 / 橫屏）、步調是否「慢得剛好」、與遊戲畫面風格是否一致；G1 試玩問卷加入「看懂了前提嗎」「有沒有想跳過」 |
